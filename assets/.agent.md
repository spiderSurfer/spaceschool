## Current Firebase Configuration

### Authentication Methods
1. **Google OAuth** (`signInWithGoogle`)
   - Uses popup flow
   - Returns `user.photoURL` for avatar display
   - Handles popup blocking gracefully

2. **Email/Password** (`signInWithEmail`, `createUserWithEmail`)
   - Custom email/password forms
   - Validates and stores credentials

3. **Passwordless Link** (`sendPasswordlessSignInLink`, `handleEmailLinkSignIn`)
   - Sends link to user's email
   - Stores email in localStorage for verification
   - Cleans up URL after completion

### Error Handling Pattern
All async functions follow this pattern:
```javascript
export async function exampleFunction(params) {
  try {
    // Firebase operation
    return result;
  } catch (error) {
    console.error('[Auth] Description:', error.message);
    throw new Error(`User-friendly message: ${error.message}`);
  }
}
```

## Code Quality Standards

### Required for All Changes
✅ **Must Have**:
- Try/catch blocks around all async operations
- Console error logging with `[Module]` prefix

❌ **Must NOT Have**:
- Hardcoded Firebase keys in production paths

- Inadequate console logging

## Common Tasks

### Add a New Auth Method
1. Create function in `auth.js` with try/catch
2. Add JSDoc comments
3. Export the function
4. Add event listener in `main.js`
5. Wire form in `ui.js` config
6. Add tests to checklist

### Update UI Configuration
Edit `defaultConfig` in `ui.js`:
```javascript
const defaultConfig = {
  navLinks: [ /* ... */ ],
  authSections: [ /* ... */ ],
  // ...
};
```

### Fix Mobile Responsive Issue
1. Check `style.css` media queries
2. Test at specific breakpoints (320px, 400px, 700px, etc.)
3. Adjust CSS variables or add media query
4. Verify keyboard navigation still works

### Add Error Handling
Wrap in try/catch:
```javascript
try {
  // operation
} catch (error) {
  console.error('[UI] Description:', error);
  // user-friendly handling
}
```
